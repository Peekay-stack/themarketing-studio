**Build order**
1. **Cutdown carries frames (the root cause).** `renderCut` (app.dc.html ~17806) sends `scenes:cr.rows` with no `frame_url`; `produceVideo` attaches `frame_url` from `sceneFrames[i]`. In `_produce_video_sync` (main.py ~1246 `segment_prompt`) the no-frame branch has no pack/cast/plate and `gemini.video(image_ref="")`; `payload['characters']` is never read there. Fix: map each cut row to its source scene (rows keep `no`; the rescript may rewrite visuals) and carry the original `frame_url` where the scene survives; for new/changed visuals generate a frame via `/scene-still` (pack + cast + plate + wardrobe + shot_size, same call the Shoot Board makes) before rendering; the `brand`-role endframe must always reuse the original pack frame. Add a pre-flight in `renderCut` (like the Production stale-frame guard): a cut with frameless shots says so and offers to generate frames. Check `_ROLE_DIRECTION` brand hold applies once frames exist.
2. **Record refs per shot at render time.** `/produce-video` returns `clips` as bare URL strings. Return per-shot `{url, provider, from_frame, refs}` (the `render()` result already has provider/from_frame; refs = cast/plate/pack the frame carried), keep `clips` for back-compat. `startCutFromFilm` (app.dc.html ~17970) must pass `refs/provider/from_frame` into beats so `continuity.provenance()` reads the record instead of inferring from the library. Persist the clip list server-side with the cut (state-only `prodClips` is lost on reload and `/cut` refuses a second start → empty `clip_url` → "No frames could be measured"). Also let the check run on a cutdown's own shots.
3. **VO pause normalisation.** Measured (Chirp en-IN Sulafat, "So do we — twenty-five parameters, every day."): em dash = 0 pause; period ≈0.15s; ellipsis 0.47s; `[pause]` markup 0.8s (needs `input.markup`, not `input.text`). Add a text normaliser in `filmvoice` before `cloudtts.synth` (and the ElevenLabs path): a dash used as a break → ellipsis (cross-engine safe) or Chirp `[pause]` markup for Chirp English; test Telugu separately (untested). Also steer the rescript prompt (`rescriptCutdown`, app.dc.html ~17709) away from em dashes for rhythm.
4. **Captions.** `filmcut.caption_cues` lays each scene's text over the DRAFT row `secs` end to end — unrelated to the beat-snapped picture (Veo 4/6/8s; picture cuts fell at 4/10/16s) and to where the voice lands. Use the real picture windows the render returns (`timecodes`/beats; same re-window `_produce_video_sync` applies to VO) or the actual VO windows. `burn_captions` hard-codes `FontName=Arial` with no `fontsdir`; bundled `api/assets/fonts/NotoSansTelugu.ttf` (also Devanagari/Kannada/Tamil/Latin) exists — add `fontsdir` + pick the font by script. This also closes the long-standing "Telugu captions may be boxes" caveat (confirmed boxes in the 20s file).
5. **`sound_plan` on the cutdown render.** `produceVideo` sends `sound_plan` (soundPlanPayload); `renderCut` does not (`rescoreCutdown` does). Add it.

An editable field (like the written look reference `videoLookRef` / `look_note`) holding the film's technical spine — camera body, lens/focal-length logic, aperture/depth of field, handheld intensity, grade, and a "no VFX / slow-mo / flare / text" negative line — restated in EVERY shot prompt in `segment_prompt` (both branches, main.py ~1246). Today the no-frame branch only has `_VID_STYLES["real"]` ("cinema camera, warm natural light") and the frame branch says "restrained" camera movement (the opposite of organic handheld); `movement_class`/camera cell are optional. Also add a shot-variety rule to the script writer (`VISUAL_RULES`, app.dc.html ~15873): mix wide / macro / close-ups. Caution: organic handheld may fight the locked product-hero endframe — keep the `brand` role HOLD.
2. **Per-element reference tagging for cast + location** (pack stays first-frame). Currently `gemini.video` sends ONE `image` and fal `video_from_image` one `image_url`. PREREQUISITE TRIAL (unverified): does Veo 3.1's API take multiple reference images, and do the fal engines (Kling/Seedance, see [[image-gen-engine-research]]) offer element tagging / multi-reference? Check current docs and run one small trial before designing.

**26 Oct — PROMPT-FRAMEWORK COMPARISON (owner's 6-part framework from the Mahabharat docx vs our prompts), audit only; two NEW findings to fold into item 1:**
(a) **The spoken line leaks into the VIDEO prompt.** `scene_text()` in `_produce_video_sync` (main.py ~1171) builds the beat as `"{tc} {visual}: {desc or dialogue}"`; rows have no `desc`, so the beat sent to Veo/fal is e.g. `0–5s Mother pours milk…: Mother (tender): ఇంకాసేపు, రాజూ — just a little more`, while the same prompt also says "No spoken dialogue". Used in BOTH branches (`Depict ONLY this beat` / `Add ONLY the motion of this beat`). The frame prompt (`frameBody`) does NOT carry dialogue. Likely harmless-to-mildly-harmful (lip movement, stray text); UNVERIFIED effect — fix is to pass visual only. Also the beat carries a timecode string.
(b) **The film's look is locked at the FRAME stage, and the frame look is stills-photography, not cinematography.** Video animates the approved frame ("treat the image as FIXED"), and `_IMG_STYLES["real"]` (main.py) reads: "photorealistic advertising photograph… full-frame DSLR, 50mm lens, shallow depth of field, crisp sharp focus… ultra-detailed" — the clean look the handout warns against; no grain/handheld/sensor-noise language; the video no-frame branch says "cinema camera" — so frame and video disagree on the camera. Any camera/lens block (item 1) must be injected at the frame stage (`/scene-still` `craft`) as well as `segment_prompt`.
Other comparison facts: our unit is ONE shot per scene (`VISUAL_RULES` forbids multiple views in a scene; `plan_by_scene` = one clip per scene, >8s splits into continuing beats) vs their 7 shots per scene; DOP/lighting/props/wardrobe department cards are 3-4 sentence free-text paragraphs (`draftDept`), not a lens/movement list; cast sheet ≤120 words with a "By scene:" version line (an advantage over theirs); other props (bag, jewellery, earphones) exist only as words — no prop images except the pack/product library kinds; location = a ≤40-word empty-place line (+ optional plate photo), deliberately stripped of people and pack.
